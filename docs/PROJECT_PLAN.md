# 当前方案与实施顺序

## 产品中心

首页只服务一个主任务：让第一次到访者先看到并理解一场英歌。木疙瘩 H5 和英歌小槌是两个次入口；人物、阵法、声场、地域和档案构成后续学习路径。

## 信息架构

```text
门厅
├─ 看英歌：完整影像与时间码解读
├─ 互动特展：木疙瘩 H5
├─ 问小槌：知识导览
└─ 在线展馆
   ├─ 识角色
   ├─ 练阵形
   ├─ 听锣鼓
   ├─ 游地域
   └─ 查档案
```

全局导航建议固定为“首页 / 在线展览 / 数字档案 / 关于项目”。页面内再使用本馆目录，不使用“二级页面”作为名称。

## 内容模型

每条展品或知识结论至少包含：

- 标题与摘要
- 证据类型：正式依据、个案证据、田野资料、展示性示意
- 来源名称与链接/档号
- 适用范围：地区、队伍、人物、板式、年代
- 记录时间与最后核校日期
- 授权状态
- 审核状态：已核实、待补证、存在冲突

## 实施优先级

### P0：核心体验闭环

1. 接入团队视频及字幕、封面、授权信息
2. 接入木疙瘩 H5，支持加载失败与返回博物馆
3. 将智能体 API 地址环境化，并完善离线/失败状态

### P1：内容可信度

1. 建立通用来源组件
2. 给人物、阵法、声场和地域结论补适用边界
3. 地图增加证据等级图例
4. IP 导览层与传统知识层使用不同视觉标签

### P2：结构与设计深化

1. 重构首页中心，减少首屏竞争
2. 固定全局导航与移动端导航
3. 降低内容页模板重复
4. Logo 开场同一会话只完整播放一次
5. 转场后恢复键盘焦点，完善 reduced-motion

### P3：后台与发布

1. 内容录入、来源审核和授权管理后台
2. 合规地图替换与审图核验
3. 部署配置、日志、速率限制和数据备份
4. 跨浏览器、性能和无障碍验收

## 内容事实边界

- `DB4405/T 315-2025` 适用于传统潮阳英歌，不等于所有地区统一标准。
- 国家级代表性项目表达应落到潮阳英歌、普宁英歌、甲子英歌等具体项目。
- “流传于某地”不等于整个行政区域都采用同一传统。
- 角色、脸谱、动作、锣鼓与阵形均应回到具体队伍、师承、年代和场景。

## 前台学习叙事

首页继续作为门厅，只保留 Logo 开场、核心判断与三件核心展项，不承担完整知识讲解。

馆藏总览承担第一次系统认识英歌的任务，阅读顺序为：

1. 英歌是什么：用身体、声音、空间、角色四个观察维度解释集体表演。
2. 起源与流变：并列呈现傩舞说、戏曲说、练武习艺说和节庆演变说，明确它们是研究假说，不写成单一起源结论。
3. 观看方法：先听共同时间，再看身体回应，随后观察队形，最后回到档案核对地区、队伍和年代。
4. 三件核心展项：团队影像负责现场，木疙瘩 H5 负责参与，英歌小槌负责追问与解释。
5. 馆藏结构：把表演、动作、人物、空间和证据记录关联起来。

专题展厅各自只回答一个中心问题：

- 看英歌：一场完整表演怎样展开。
- 识角色：角色功能、脸谱、服饰和器物如何共同完成辨认。
- 练阵形：站位、路线和边界如何组织集体空间。
- 听锣鼓：鼓、锣钹、槌击和吆喝如何组织共同时间。
- 游地域：同叫英歌的不同地区与队伍为何各有版本。
- 查档案：一个结论来自哪里，适用于什么范围。

## 前台动效职责

- 定义图的四个观察维度可以点击切换，环形结构只用于表达各要素围绕同一场表演协同。
- 起源时间线按阅读顺序显影，四种起源假说由访客主动切换，不自动轮播。
- 观看方法按“听见、看见、跟随、核对”的顺序进入，帮助建立观看路径。
- 页面转场继续使用现有波形变形，承担展厅切换提示。
- 所有新增动画只使用位移、旋转与透明度，并提供 reduced-motion 静态版本。

本馆与一般资料站的核心差异是：同一内容同时保留现场感、结构解释与证据边界，使访客能够看见、理解并核对。
