# 当前方案与实施顺序

## 产品中心

首页只服务一个主任务：让第一次到访者先看到并理解一场英歌。木疙瘩 H5 和英歌小槌是两个次入口；人物、阵法、声场、地域和档案构成后续学习路径。

## 信息架构

```text
门厅
├─ 看英歌：完整影像与时间码解读
├─ 互动特展：木疙瘩 H5
├─ 问小槌：知识导览
└─ 在线展馆
   ├─ 识角色
   ├─ 练阵形
   ├─ 听锣鼓
   ├─ 游地域
   └─ 查档案
```

全局导航建议固定为“首页 / 在线展览 / 数字档案 / 关于项目”。页面内再使用本馆目录，不使用“二级页面”作为名称。

## 内容模型

每条展品或知识结论至少包含：

- 标题与摘要
- 证据类型：正式依据、个案证据、田野资料、展示性示意
- 来源名称与链接/档号
- 适用范围：地区、队伍、人物、板式、年代
- 记录时间与最后核校日期
- 授权状态
- 审核状态：已核实、待补证、存在冲突

## 实施优先级

### P0：核心体验闭环

1. 接入团队视频及字幕、封面、授权信息
2. 接入木疙瘩 H5，支持加载失败与返回博物馆
3. 将智能体 API 地址环境化，并完善离线/失败状态

### P1：内容可信度

1. 建立通用来源组件
2. 给人物、阵法、声场和地域结论补适用边界
3. 地图增加证据等级图例
4. IP 导览层与传统知识层使用不同视觉标签

### P2：结构与设计深化

1. 重构首页中心，减少首屏竞争
2. 固定全局导航与移动端导航
3. 降低内容页模板重复
4. Logo 开场同一会话只完整播放一次
5. 转场后恢复键盘焦点，完善 reduced-motion

### P3：后台与发布

1. 内容录入、来源审核和授权管理后台
2. 合规地图替换与审图核验
3. 部署配置、日志、速率限制和数据备份
4. 跨浏览器、性能和无障碍验收

## 内容事实边界

- `DB4405/T 315-2025` 适用于传统潮阳英歌，不等于所有地区统一标准。
- 国家级代表性项目表达应落到潮阳英歌、普宁英歌、甲子英歌等具体项目。
- “流传于某地”不等于整个行政区域都采用同一传统。
- 角色、脸谱、动作、锣鼓与阵形均应回到具体队伍、师承、年代和场景。
