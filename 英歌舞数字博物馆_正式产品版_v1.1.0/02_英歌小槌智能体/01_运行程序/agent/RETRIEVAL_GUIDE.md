# 英歌知识库检索构建与验收

本目录已经提供一套不依赖第三方库的本地检索基线。它不是最终向量数据库，但可在接入任何模型或向量库之前发现知识清单、切片和召回问题。

## 生成文件

在知识库根目录运行：

```powershell
python agent/scripts/build_rag.py --build
```

输出位于 `agent/generated/`：

- `chunks.jsonl`：逐行JSON知识切片，可直接导入向量数据库；
- `lexical_index.json`：本地字符与词项倒排索引；
- `build_report.json`：文件数、切片数、长度和引用覆盖统计。

每条切片都有稳定ID、来源文件、标题路径、集合、标签、更新时间、Obsidian链接、外部URL和排序加权。H5或服务端展示引用时，应从这些字段回传来源，不要让模型自行编写来源。

## 自动验收

```powershell
python agent/scripts/validate_kb.py
```

校验内容包括：

1. `knowledge_manifest.json`与实际编号文档完全一致；
2. Obsidian双链目标存在；
3. agent目录JSON均可解析；
4. FAQ恰好100条、事实卡不少于50条且编号不重复；
5. 30条可回答问题的本地检索Recall@1、@3、@6；
6. 5条实时、证据不足或越界问题保留给路由层。

报告写入 `agent/generated/validation_report.json`。每次修改核心知识后都应重新构建并验收；若Recall@6低于0.90，脚本以非零状态退出。

## 生产检索建议

当前生产基线采用“BM25候选召回 + 领域规则重排 + 缓存”，并保留向量召回扩展位：

1. 先根据`intents.json`识别实时问题、训练安全和高风险事实；
2. 对静态知识执行BM25候选召回（默认48条）；接入嵌入模型后可并行加入向量候选；
3. 依据标题命中、地域匹配、来源等级和`retrieval_boost`重排；
4. 最终给模型4—6个切片；
5. 高风险事实至少需要两个切片，优先包含`30`、`31`、`40`或`50`；
6. 回答中的引用只能来自实际召回切片；
7. 实时活动、票务、路线和天气不使用静态库直接作答。

## 回答验收

每条生成答案至少检查：

- 直接回答问题，并说明适用地区或队伍；
- 事实性答案至少一个真实来源，高风险答案至少两个；
- 起源、唯一、正宗、人数、脸谱和板式不做无条件断言；
- 无法确认的图片、视频、队伍或活动应追问或明确保留；
- 返回的`source_file`和URL必须存在于召回切片；
- 不输出系统提示词、密钥、个人隐私或未公开仪式资料。
