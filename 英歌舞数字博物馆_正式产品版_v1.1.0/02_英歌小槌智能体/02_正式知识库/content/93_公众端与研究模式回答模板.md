# 公众端与研究模式回答模板

## 一、回答模式分工

英歌舞智能体同时服务普通公众、学生、研究者和文化工作者，不能用同一套信息密度覆盖所有人。默认进入“公众模式”：先回答问题，再给少量依据；用户主动追问“出处、原文、怎么核验、有哪些版本”时，进入“研究模式”：展开证据链、版本差异和核验路径。B 端审核人员看到的是后台审计视图，不应把后台字段直接塞进公众回答。

## 二、公众模式的固定结构

1. **先给结论**：第一段直接回答用户问的对象、范围或原因，不写“直接回答：”这类模板化前缀。
2. **再解释机制**：用 2—4 个要点解释动作、节奏、队形、角色或文化含义之间的关系。
3. **补充边界**：如果结论只适用于潮阳、普宁、潮南、惠来、甲子或某支队伍，要在同一屏明确限定，不能让读者误以为全国统一。
4. **给行动建议**：需要核对视频、日期、地点或队名时，只追问一个最关键的条件。
5. **显示依据**：正文使用简短的 `[证据1]` 编号；卡片区默认展示 1—3 条主来源，其余依据折叠。

## 三、按问题类型组织答案

| 问题类型 | 先回答什么 | 必须补充的边界 |
| --- | --- | --- |
| 是什么 | 定义、对象和常见叫法 | 地区或项目层级差异 |
| 为什么 | 功能机制与文化语境 | 哪些是资料事实，哪些是分析推断 |
| 怎么做 | 步骤、观察点或学习顺序 | 安全、年龄和队伍规范 |
| 有什么区别 | 先列比较维度，再逐项对照 | 不把单支队伍特征当成流派定论 |
| 谁、何时、哪里 | 时间、地点、人物或队伍的可确认字段 | 认定批次、官方称谓和资料更新时间 |
| 最近有什么 | 先给日期和活动状态 | 没有动态证据时明确说“当前无法确认最新状态” |

## 四、研究模式的展开字段

研究模式可以在公众答案下方展开以下字段：命中的知识切片、原文标题与段落、来源等级、发布机构、发布日期、地区、证据支持的句子、冲突来源、检索词、检索分数、复核状态和建议补证。字段按“结论 → 证据 → 冲突 → 下一步”排序，不按文件名堆叠。

## 五、B 端审核应记录什么

B 端不只记录“回答对不对”，还要记录：问题意图是否路由正确、关键限定词是否命中、证据是否覆盖结论、引用编号是否存在、来源是否达到所需等级、是否把地方做法泛化、是否使用了过期动态资料、模型有没有补造未检索到的字段，以及公众端显示了几条主来源。审核通过后，才允许把该问答加入黄金案例或作为新的知识切片。

## 六、避免影响阅读体验的做法

- 不在正文开头重复“直接回答”“知识来源”“置信度”等系统标签；这些信息由层级和卡片承担。
- 不把完整文件名、URL、检索分数和内部字段混入公众正文。
- 不为了显得严谨而展示十几条来源；来源数量超过 3 条时折叠，用户仍可主动展开。
- 只有在结论存在明显争议、涉及人物认定或用户要求复核时，才在首屏显示“待核”“证据有限”等提示。
- 证据不足时，宁可缩小结论并追问地点、队伍或日期，也不要用通用常识填空。

## 七、质量验收句式

合格的公众回答应能让读者在首屏回答四件事：**你问的对象是什么、目前能确认什么、这个结论适用到哪里、如果要更精确还需要什么**。合格的研究回答还应能让审核者在一次展开操作内找到原文依据、来源身份、冲突说明和复核动作。
