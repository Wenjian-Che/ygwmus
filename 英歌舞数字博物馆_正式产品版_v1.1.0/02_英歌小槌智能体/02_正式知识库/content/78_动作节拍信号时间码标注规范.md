# 英歌动作、节拍与信号时间码标注规范

## 如何给英歌视频做动作、鼓点和队形的时间码标注

不要只写一列动作名称。应在同一时间码上并列记录**声音轨、身体动作轨、队形空间轨和证据轨**：声音轨标鼓、锣、槌击、吆喝与哨声；身体轨标脚步、重心、转槌与击槌；队形轨标开合、穿插、转向和交叉点；证据轨标镜头连续性、原声与音画同步状态。这样才能回答“哪一个声音信号之后开始换动作或变队形”，同时避免把剪辑造成的先后关系误判为队伍约定。

## 一、这套规范解决什么问题

仅写“舞者跟着鼓点变阵”不能支持细致问答。智能体若要回答“哪一拍开始换步”“谁先发信号”“鼓点变急后队形如何变化”，必须把声音、身体和空间放在同一时间轴上。

本规范用于研究记录、视频检索和智能体证据引用，不是任何队伍的传统鼓谱，也不替代传承人的现场教学。

## 二、三个证据层必须分开

| 层级 | 含义 | 示例写法 |
|---|---|---|
| 来源事实 | 官方资料或队伍口述明确陈述 | “汕尾市政府资料称甲子英歌动作变化前有八拍吆喝。” |
| 影像观察 | 记录者能在连续原视频中直接看见或听见 | “00:42.160出现领喊，00:46.020前排开始横移。” |
| 分析推断 | 根据前后关系提出的解释 | “该领喊可能承担下一段准备信号，需司鼓或头槌确认。” |

标注字段中的 `evidence_type` 必须取 `source_fact`、`direct_observation` 或 `analytical_inference`。不能把“先发生”自动写成“导致”。

## 三、最小标注单元

每个事件用半开区间 `[t_start, t_end)` 表示，至少保留到毫秒。无法确定结束点时，可标记为点事件，并说明误差范围。

```yaml
annotation_id:
media_id:
team:
place:
event_date:
t_start: "00:00:42.160"
t_end: "00:00:46.020"
frame_start:
frame_end:
time_uncertainty_ms:
track: audio/body/formation/context
event_type:
label_original:
label_normalized:
performer_or_channel:
beat_cycle_id:
beat_index:
evidence_type:
confidence: high/medium/low
source_or_observer:
note:
```

### 四条轨道

1. **声音轨**：大鼓、锣、钹/镲、槌击、领喊、群喊、哨声、环境声。
2. **身体轨**：手和槌、脚步、重心、躯干、头部、朝向、角色性动作。
3. **队形轨**：开合、分列、穿插、转向、交叉点、队列间距和领队路线。
4. **情境轨**：入场、定点、转角、观众侵入、镜头切换、变速、扩声和配乐替换。

## 四、动作相位怎么标

为了跨视频检索，可把一个动作分析为六个研究相位。它们是分析标签，不是队伍自己的术语：

| 相位 | 记录问题 |
|---|---|
| 准备 `prepare` | 重心和槌位如何预置？ |
| 驱动 `drive` | 哪个关节或脚步首先启动？ |
| 接触 `contact` | 槌在何处、与谁、以何方向接触？ |
| 回弹 `rebound` | 接触后如何卸力或转换轨迹？ |
| 恢复 `recover` | 身体如何回到可继续动作的位置？ |
| 转换 `transition` | 下一动作、步法或队形何时开始？ |

若动作没有实际对击，`contact` 可改为轨迹的视觉顶点，但必须注明 `no_physical_contact: true`。

## 五、八拍和循环的记录

“八拍”首先是一组本地信号结构，不能预设等于现代音乐中的固定拍号。

```yaml
cycle_id: JZ-CALL-001
cycle_basis: team_statement
count: 8
tempo_bpm: null
tempo_method: not_measured
beats:
  - index: 1
    vocal_role: 头槌李逵与二槌杨志
  - index: 2
    vocal_role: 头槌李逵与二槌杨志
  - index: 3
    vocal_role: 头槌李逵与二槌杨志
  - index: 4
    vocal_role: 头槌李逵与二槌杨志
  - index: 5
    vocal_role: 全体舞者
  - index: 6
    vocal_role: 全体舞者
  - index: 7
    vocal_role: 全体舞者
  - index: 8
    vocal_role: 全体舞者
next_action_start: 待同步视频核验
```

上例只表达甲子官方文字明确的领喊分工，不能补造每个字的落拍、鼓槌配器或第八拍后具体接哪个动作。

## 六、帧率、剪辑和音画同步

### 原始帧率

- 保存容器帧率与实测帧率；
- 可变帧率视频必须保留原始时间戳，不能只按“帧号÷标称帧率”计算；
- 手机慢动作需要记录拍摄帧率、导出帧率和播放倍率。

### 镜头切换

一次切镜就中断连续动作证据。切镜前后即使人物姿态相近，也不能自动拼成一个动作循环。

### 音画漂移

用槌体接触、落脚或可见鼓槌落点检查声画偏差。若开头和结尾偏差不同，说明可能存在渐进漂移，应分段校正，不能只设一个全片偏移量。

### 配乐替换

若现场声被音乐覆盖，视频仍可分析服饰和部分队形，却不能用于证明鼓句、槌击声或吆喝与动作的同步关系。

## 七、完整示例：不虚构秒数的甲子标注包

```yaml
case: 甲子动作转换
verified_from_public_source:
  - 动作变化前有八拍吆喝
  - 前四拍由头槌李逵与二槌杨志领喊
  - 后四拍由全体舞者回应
  - 鼓点变急时可出现合拢、分行、穿8字、穿双龙、穿龙仔
requires_video_annotation:
  - 八拍开始和结束时间
  - 领喊具体字词及延音
  - 锣鼓是否在吆喝中保持原循环
  - 下一动作从第几拍或拍后开始
  - 变阵由时迁、李逵或队列视觉信号中的哪一项确认
forbidden_inference:
  - 给每种阵形编造固定鼓语
  - 把甲子八拍推广为全部英歌
```

## 八、给智能体的检索粒度

每条同步知识至少生成四种检索入口：

- `队伍 + 动作名`
- `声音信号 + 角色`
- `队形 + 转换条件`
- `视频问题 + 证据限制`

回答时优先返回队伍级事实；若用户未给队伍，应先解释通用机制，再用甲子、桃园或古帅等具名个案举例。

## 九、来源

- 汕尾市人民政府《国家级非遗之甲子英歌》：甲子动作、步法、八拍吆喝和鼓点变急时的队形变化。
- 中国非物质文化遗产网《英歌（潮阳英歌）》：慢板、中板、快板的动作组与鼓点差异。
