# 英歌舞智能体产品设计与知识架构

知识回答的事实基准为 [[50_核心事实注册表]]，来源等级与引用格式遵循 [[31_权威来源与参考书目]]。

## 产品定位

智能体不是“会背英歌资料的聊天框”，而应承担五类任务：

1. **知识讲解**：回答历史、表演、角色、地域、非遗等问题。
2. **看演出助手**：解释眼前的角色、槌法、队形、锣鼓和流程。
3. **研学导览**：按年龄、时长和场景生成学习路线。
4. **研究助手**：给出来源、争议、田野调查和资料整理建议。
5. **互动传播**：测验、角色卡、知识地图和推荐阅读。

不建议首版直接提供：

- 根据模糊照片断言人物身份；
- 没有队伍来源的脸谱“算命式”识别；
- 替代传承人教授高强度动作；
- 无来源生成具体传承人身份、队伍荣誉或活动时间；
- 自动使用用户上传影像进行商业训练或二次发布。

## H5首页建议

### 首屏快捷问题

- 英歌和英歌舞是同一个吗？
- 为什么舞者要拿两根木槌？
- 快板、中板、慢板有什么区别？
- 英歌一定有108个人吗？
- 我正在看一场表演，应该观察什么？
- 帮我规划一条30分钟入门路线。

### 功能入口

| 入口 | 智能体行为 | 知识来源 |
|---|---|---|
| 问英歌 | 通用检索问答 | 全库 |
| 看懂表演 | 按“角色—动作—队形—锣鼓”追问 | 03、14—17、22—24 |
| 地域地图 | 先问地点，再返回地方版本 | 18、25 |
| 研学课堂 | 询问年龄、时长、人数 | 26、28 |
| 研究与引用 | 默认显示来源等级和待核项 | 10、27、31 |
| 辨别真假 | 对网络说法进行证据分级 | 30、31 |

## 回答结构

默认答案采用四层，可根据H5界面折叠：

1. **直接回答**：1—3句给结论。
2. **补充说明**：说明地域差异或历史边界。
3. **证据标签**：A/B/C/D级、来源标题与链接。
4. **继续探索**：提供2—3个相关问题，不重复当前问题。

示例：

```text
英歌没有统一规定必须是108人。国家级非遗名录资料记载，
舞者通常为双数，少则12人、多至108人；具体人数会随队伍
传统、巡游路线和舞台空间调整。

[证据 A] 国家级非遗名录资料
[地区] 普宁、潮阳的概括性资料
[继续了解] 为什么常用双数？头槌和二槌负责什么？
```

## RAG检索策略

### 切块

- 每块建议300—700个中文字符。
- 标题路径必须进入元数据，如“表演形式 > 音乐与节奏 > 伴奏乐器”。
- 表格可整体保留；超过700字时按行组拆分并重复表头。
- 不将YAML头部作为正文嵌入，但提取tags、aliases、status。
- “警告、辨析、来源”块应设置更高检索权重。

### 元数据

每个知识块至少包含：

```json
{
  "chunk_id": "KB03-音乐与节奏-001",
  "title": "英歌舞 - 表演形式",
  "heading_path": ["音乐与节奏", "伴奏乐器"],
  "region": ["通用"],
  "topics": ["表演", "锣鼓"],
  "claim_type": "确证事实",
  "source_grade": "A",
  "updated": "2026-07-28",
  "file": "03_表演形式.md"
}
```

### 排序

推荐综合分：

`语义相似度 × 0.55 + 标题命中 × 0.15 + 地域匹配 × 0.15 + 来源等级 × 0.10 + 时效 × 0.05`

若问题包含村名、队名或“我们这里”，地域匹配权重提升至0.30。若问题是“真的假的”“有依据吗”，优先召回30、31及带warning的块。

## 对话状态

智能体最多保留以下结构化状态：

```json
{
  "audience": "游客|学生|教师|研究者|队员|未知",
  "region": "普宁|潮阳|潮南|惠来|潮州|其他|未知",
  "scene": "通用问答|现场看演出|研学|训练|研究",
  "age_group": "儿童|青少年|成人|未知",
  "detail_level": "简短|标准|深入",
  "source_mode": "隐藏|简要|完整"
}
```

不要保存身份证号、联系方式、精确住址、未成年人面部数据或宗教活动内部信息。

## 首版验收指标

| 指标 | 目标 |
|---|---:|
| 核心FAQ正确率 | ≥95% |
| 回答附可追溯来源率 | ≥90% |
| 地区差异问题主动限定率 | ≥90% |
| 无依据数字编造率 | 0 |
| 平均首字延迟 | H5目标≤2秒 |
| 移动端首屏答案长度 | 80—180字 |
| 用户追问完成率 | 持续观察 |

## 推荐上线顺序

1. 纯文本RAG问答；
2. 引用卡片和相关问题；
3. 地域筛选与知识地图；
4. 图片辅助理解（只描述可见元素，不强判角色）；
5. 活动日历、队伍动态等实时数据；
6. 经过授权的动作视频库与多模态检索。

实时活动、票务、路线、天气和队伍演出安排不能只依赖静态知识库，需要独立的实时数据接口。
